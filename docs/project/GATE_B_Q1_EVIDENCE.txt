PINNED TIMING AUDIT

timing.teleop_sample_fps: RESOLVED AS 30 Hz

- Upstream/default behavior, not a project safety threshold: pinned LeRobot 0.6.1
  commit 7e241bd630a3719a56157a497ce5d08f244784f1 defines FPS = 30 in
  examples/isaac_teleop_to_so101/common.py and paces teleoperate.py at 1/FPS.
- The same pinned version's DatasetRecordConfig defaults fps to 30, and record.py
  passes the selected dataset fps into a 1/fps paced recording loop.
- tools/quest_xr_diagnostics.py defaults to a 0.25 s evidence-report sample period.
  That 4 Hz diagnostic display/polling default is not the teleoperation runtime
  cadence and is not used as timing.teleop_sample_fps.

timing.stale_behavior: RESOLVED

- Project safety behavior supported by physical Q1 and pinned upstream behavior:
  an unavailable, inactive, invalid, or malformed controller sample is not a
  valid/fresh pose and must not be used; pose use resumes only after a newly valid
  tracked sample is available.
- Isaac Teleop 1.3.131 ControllerTracker reports data=None when a controller is
  inactive. ControllersSource emits an absent optional group in that case and
  carries the upstream grip/aim validity flags for active data.
- The pinned LeRobot XR controller treats an absent or malformed controller group
  as not tracked and returns neutral pose/controls so its owning loop freezes/holds.
- The physical Q1 tracking-loss and recovery observations confirm this behavior on
  Quest 3. No robot/CAN command behavior was exercised or inferred.

timing.max_xr_pose_age_ms: BLOCKED / NULL

- This field is a project safety limit, not an observed/default upstream value.
- Isaac Teleop 1.3.131 defines monotonic sample timestamps on
  ControllerSnapshotRecord, but ControllerTracker returns ControllerSnapshotTrackedT,
  whose public interface contains data only. The selected ControllersSource consumes
  that timestamp-free tracked value and does not define or enforce a maximum age.
- Pinned LeRobot 0.6.1 defines no numeric XR pose-age limit in this integration.
- A 30 Hz loop has a nominal 33.333 ms period, but a sampling period is not evidence
  for a permissible safety age and is not converted into a threshold here.
- Required decision: the project safety owner must select max_xr_pose_age_ms from a
  control/safety analysis and identify the timestamped measurement/enforcement
  boundary. No value is guessed in this audit.
